## 基线与目标

- `main` 已合入上游 `2.7.1`（`6759e35`）和 Codex Design `0.5.3` 的完整历史。
- 正式市场仍引用 `codex/plugin`；已安装 `0.6.1`。历史预览、字体解码、画布编辑后关闭重开、只读参考和设计系统单文件导出已实际复验；Dashboard 与剩余格式继续验收。
- 初次同步时，新文案和服务器锚点变化触发了构建保护。候选版已适配这些契约并保留未知结构明确失败的规则，不能仅凭版本号或构建成功发布。
- 目标是吸收可靠性、导出和恢复能力，保留已经确定的 Codex 原生交互。

## 保留的产品规则

- 全局作品库仍为 `~/.codex/CodexDesignLibrary`，使用全局 Codex Design 工作区和默认本机环境。
- 批注先 Add to chat，用户通过底部原生 Send 发送；每条实际收到的请求独立读取、接受、派发。主代理决定复用、恢复或新建真实子代理。
- 保留现有自动保存、保存前刷新、修改版本校验、AI 前恢复点、批注回复与解决/重开。
- 导入导出只包含作品内容，排除聊天、批注、历史、worker、凭据和运行状态。
- 设计系统作为只读参考使用；修改其源作品不会自动改变其他作品。
- 插件界面保持英文；保留已确认的评论头像圆点、原生主题适配、菜单位置和另存为流程。

## 第一批：下一开发版的必做项

### A01 · P0 · 适配新上游的构建与原生桥接

- [ ] 更新五个技能的宿主文案和引用映射；新增的 Claude Data 等内容要核实语义，映射到真实可用的本地能力。
- [ ] 适配四类编辑器的新服务器路由、保存入口、资源加载和新版 vendor 补丁锚点。
- [ ] 保留批注、属性面板、菜单、字体主题、原生传输和资源策略的现有适配。
- [ ] 明确排除 Share/Copy link 自动开启局域网的副作用；普通打开和复制原生作品链接保持本机流程。
- [ ] 锚点、格式或协议不匹配时继续明确失败，不静默跳过补丁。

验收：构建、生成一致性和便携验证通过；路径不依赖用户名、Node 安装位置或工作目录；新插件在实际 Codex 宿主正常加载五技能和六工具。

### A02 · P0 · 保存冲突与并发写入可靠性

依赖：A01；Dashboard 明确覆盖语义依赖新版合并/历史基线，不作为孤立补丁直接搬运。

- [ ] 接入保存起始版本校验，处理缺少基准版本和保存期间文件变化。
- [ ] 不同字段/元素的修改按新版规则保留；同一位置冲突给出明确选择，不能静默覆盖。
- [ ] Dashboard 并发首次创建时保留双方字段，冲突字段可追踪。
- [ ] Dashboard 提示覆盖后再次明确 Save，按用户主动选择覆盖处理。
- [ ] 接回现有原生保存屏障、恢复点和独立请求版本保护，不放宽 worker 写入所有权。

验收：人工编辑与 AI 交错保存、不同位置修改、同位置冲突、并发首次创建、主动覆盖、旧批注失效分别有回归；内容不会因代理重试被重复覆盖。

### A03 · P0 · TUN/代理环境下的打开稳定性

- [ ] 吸收代理网卡导致所有端口似乎有响应时的端口探测修复。
- [ ] 保留当前作品身份校验、失效服务恢复、端口复用防串作品规则。
- [ ] 重复打开复用已有作品 Tab，不新增 localhost 浏览器 Tab。

验收：正常网络、端口实际占用、TUN 场景、旧服务退出、端口被其他程序复用分别验证。不能以绕过作品身份校验来解决端口问题。

### A04 · P0 · 四类编辑器的真实宿主回归

依赖：A01—A03。

- [ ] Slides、Design、Design System、Dashboard 的创建、重命名、保存、关闭重开、属性与更多菜单逐类检查。
- [ ] 检查批注、回复、解决、重开、追加意见，以及非评论 AI 修复入口。
- [ ] 验证 Add to chat 不自动发送；实际 Send 后才派发，原有子代理复用和回帖恰一次。
- [ ] 从 0.5.3 升级时，验证旧缓存不存在或只剩空目录的绑定迁移。
- [ ] 保留画板尺寸与 `$preview` 同步、英文界面和宿主主题适配等已修复行为。

验收：使用最终 GitHub 市场安装包，在 Codex 真实面板操作并保留截图、文件检查和请求证据；网页预览不能代替宿主验收。

### A05 · P0 · 补齐已知导出覆盖缺口

- [ ] 设计系统单文件导出。
- [ ] 有真实测试数据的 Dashboard CSV 导出。
- [ ] Canvas 其余实际提供的导出格式，按真实菜单列清矩阵，不把 PNG 通过扩展成其他格式通过。
- [ ] 验证指定目录、取消无写入、覆盖确认、失败提示和作品内容隔离。

验收：检查实际落盘位置、文件内容和可打开性。HTML 交互只使用允许的验证方式；受工具策略限制时保留未验项，不绕过限制或伪称通过。

## 第二批：高价值功能，地基稳定后逐项接入

### B01 · P1 · 字体随导出打包

依赖：A01、A05。

- [ ] 吸收 HTML/PPTX/Standalone 的字体收集、Unicode 分片/子集及 16 MiB 上限改进。
- [ ] 保留字体来源信息和明确的失败/降级提示。
- [ ] 验证中文、英文、粗体及实际支持的字体变体；在 PowerPoint 中打开检查，不能只沿用原有 Arial 样例。

收益：减少导出后换字体、缺字和版式变化。

### B02 · P1 · 导出 HTML 的跨画板导航

依赖：A01、A05。

- [ ] 支持导出后从画板 A 点击相对链接打开画板 B，以及 Back 返回。
- [ ] 保留目标画框尺寸和相关资源，区分内部画板与外部链接。
- [ ] 检查相对路径、缺失目标、循环跳转和目录移动后的行为。

收益：导出的多页面设计仍可作为交互原型使用。

### B03 · P1 · Theme 内查看只读设计系统

依赖：A01。

- [ ] 从作品 Theme 打开当前已安装参考的颜色、文字样式、token、组件和指南。
- [ ] 明确查看的是作品使用的参考副本/版本；与源设计系统的更新分开。
- [ ] 在只读展示中禁止执行项目脚本或跟随文件系统链接读取库外文件。

收益：设计时直接查规范，不需要跳出作品寻找文件，也不增加自动联动。

### B04 · P1 · 历史差异、预览与局部恢复

依赖：A01、A02；先确定与现有全局库快照的一致模型。

- [ ] 复用现有 History 入口，区分 AI 前整作品恢复点与更细的编辑记录，避免两套重复历史菜单。
- [ ] 增加按文件、元素、行和 token 展示的差异，以及修改者和版本预览。
- [ ] 支持只恢复选定改动；恢复产生新版本，保留其他后续修改。
- [ ] 有进行中的 AI 写入时，继续遵守现有所有权和恢复约束。
- [ ] 历史仍不进入作品的内容导出包。

收益：找回被覆盖的局部内容，减少为了恢复一点修改而回滚整个作品。

### B05 · P1 · 统一导出入口与反馈

依赖：A05；需要时结合 B01、B02。

- [ ] 参考上游按格式列出图标、说明和可用范围，但放进现有合适的编辑器菜单。
- [ ] 延续当前 Save As，不改回项目 `exports/` 固定落盘。
- [ ] 区分作品内容包、PDF/PPTX/图片/HTML，避免把运行目录原样打包。

收益：四类编辑器导出操作一致，用户清楚导出什么、保存在哪里。

## 不重复建设或直接照搬

- DSH 专属 Artifacts 侧栏、对话 Browser 打开方式和 shell 命令识别。
- DSH 将所有下载固定存到 `exports/` 的策略。
- 上游包含历史或批注的整文件夹 ZIP 语义。
- 我们已有的全局作品库、整作品快照、原生草稿/Send 和子代理批注控制器。
- 已取消的中英文切换，或已接受保留的宿主顶部/共享中栏限制。

建议顺序：**A01 → A02/A03 → A04/A05 → B01/B02/B03 → B04/B05**。阶段内按依赖安排验证，阶段结束后再决定新版本范围；本清单不代表这些功能已经发布。
